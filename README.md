# Hey, I'm here

I spend most of my time in the terminal. Python is my main language because it lets me move quickly from idea to working script without fighting the syntax. When something needs to run every night or every hour, I reach for simple automation tools and keep the setup as plain as possible.

Open source has been the best way I've found to learn. Reading other people's code teaches patterns that tutorials skip. Contributing small fixes or documentation updates is how I stay connected to projects I care about. I try to keep my own repositories public whenever the code is useful beyond my own machine.

Linux is the environment I prefer for almost everything. Once the system is set up the way I like it, the rest of the work feels lighter. I still experiment with different distributions and shell configurations, mostly out of curiosity rather than necessity.

### What I tend to work on

- Writing scripts that remove repetitive tasks from my day
- Exploring how different tools fit together in small pipelines
- Keeping notes on what works and what breaks so I don't have to relearn it later

I don't keep a long list of public achievements or polished project showcases. Most of the useful work stays close to home until it's ready to share. If you find something interesting in one of the repositories, feel free to open an issue or send a pull request. Clear feedback is always welcome.

Outside of coding I like walking without a destination and reading technical writing that doesn't try too hard to be clever. The goal is usually the same: understand the system well enough that the next change feels obvious.

Thanks for stopping by.
